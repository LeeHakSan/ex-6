# 계획·실행·돌아보기 (T06)

계획 → 할 일 → 실행 기록 → 돌아보기 → 다음 계획으로 이어지는 개인용 계획 관리 앱.
프론트엔드(HTML/CSS/바닐라 JS)가 Supabase(Postgres, REST)에 anon key로 직접 접속한다. 별도 백엔드 서버 없음.
배포: Vercel 정적 사이트. 로그인 없음(누구나 링크로 접근 가능, 첫 화면에 고지).

## 1. Supabase 설정
1. https://supabase.com 에서 새 프로젝트를 만든다.
2. 프로젝트의 SQL Editor에 `sql/schema.sql` 전체 내용을 붙여넣고 실행한다.
3. Project Settings → API에서 **Project URL**과 **anon public key**를 확인한다. (service_role key는 절대 사용하지 않는다.)
4. `js/supabaseClient.js`의 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 위 값으로 교체한다.

## 2. 로컬 확인
빌드 없이 정적 파일이므로 아무 정적 서버로 열면 된다. 예:
```
npx serve .
```
`js/supabaseClient.js`를 설정하지 않으면 화면 상단에 빨간 경고 배너가 뜬다.

## 3. Git / Vercel 배포
```
git add .
git commit -m "init: T06 계획 관리 앱"
git remote add origin <내 GitHub 저장소 URL>
git push -u origin main
```
Vercel: `npx vercel login` 으로 로그인한 뒤 `npx vercel --prod`로 배포(둘 다 브라우저 인증이 필요해 사용자가 직접 실행). 빌드 명령 없이 루트를 그대로 정적 배포하면 된다.

## 4. 배포 후 반드시 할 일 — 내 실제 데이터 채우기
과제 통과 기준(C78~C81)이라 더미 데이터가 아니라 실제 데이터가 있어야 한다.
- 계획 1개 이상 (지금 실제로 하고 있는 일)
- 그 계획에 딸린 할 일 5개 이상
- 실제 실행 기록 3개 이상
- 위 데이터로 돌아보기 화면의 집계 숫자가 0이 아닌지 확인

## 5. 짧은 확인 방법 (제출용)

| 항목 | ① 어디로 | ② 무엇을(3단계 이내) | ③ 통과 조건 | ④ 실패 조건 |
|---|---|---|---|---|
| 계획 수정 이력 | 계획 탭 | 계획 하나 수정 → "수정 이력 보기" 클릭 | 수정 전 값이 이력 목록에 남아 있음 | 이력이 비어 있거나 수정 전 값이 사라짐 |
| 완료 연타 멱등 | 할 일 탭 | 진행 중 할 일의 "완료" 버튼을 빠르게 두 번 클릭 | 완료 배지 1개, 돌아보기 완료 수가 정확히 +1 | 완료 수가 +2 되거나 오류 발생 |
| 정렬/검색/필터 | 할 일 탭 | 정렬 기준 변경 → 화면 상단 "정렬 기준:" 문구 확인 | 문구가 실제 정렬 결과와 일치 | 정렬 기준이 안 보이거나 결과와 다름 |
| 실행 기록 종속 | 할 일 탭 | 할 일의 "실행 기록/상세" 클릭 → 기록 추가 | 그 할 일의 기록 목록에만 추가됨, 계획 예상 시간 불변 | 다른 할 일에 섞이거나 예상 시간이 바뀜 |
| 돌아보기 드릴다운 | 돌아보기 탭 | "완료"/"지연"/"막힘" 숫자 클릭 | 할 일 탭으로 이동, 그 숫자에 해당하는 목록만 보임 | 필터 없이 전체가 보이거나 이동하지 않음 |
| 다음 계획 이월 | 돌아보기 탭 → 계획 탭 | 고칠 점 저장 → 새 계획 만들기 폼 열기 | "이전 계획에서 넘어온 메모"에 방금 저장한 문구가 채워짐 | 빈칸이거나 다른 문구 |
| 내보내기 | 헤더 | "내 데이터 내보내기" 클릭 → 새로고침 | JSON 파일 1개 다운로드, 새로고침 후 화면 값 동일 | 파일이 안 열리거나 값이 달라짐 |
| 스크립트 방어 | 할 일 탭 | 제목에 `<script>alert(1)</script>` 입력 후 저장 | 글자 그대로 화면에 보이고 알림창이 뜨지 않음 | 알림창이 뜨거나 스크립트가 실행됨 |
| 공개 접근 | 배포 URL | 시크릿 창에서 URL 접속 | 로그인 없이 바로 화면이 뜨고 상단에 공개 안내 문구가 보임 | 로그인/가입 화면이 뜨거나 안내 문구가 없음 |

## 6. AI 활용 내역
> 실제 구현 후 본인 기준으로 다시 확인하고 필요하면 고쳐서 제출할 것.

- **AI(Claude)에게 맡긴 일**: 과제 카드 5장(계획/할 일/실행 기록/돌아보기/공개·보안) 요구사항을 체크리스트로 정리, DB 스키마 설계(`sql/schema.sql`, `contracts/schema-v2.json`), 프론트엔드 전체 코드(HTML/CSS/JS) 초안 작성.
- **내가 직접 판단한 일**: 프론트 HTML/JS/CSS + Supabase + Vercel 스택 선택, 완료 멱등·수정 이력·다음 계획 이월 같은 요구사항을 어떤 데이터 구조로 풀지에 대한 최종 확인, 실제 계획·할 일·실행 기록 데이터 입력.
- **AI 제안을 따르지 않은 일**: 원래 "자바 백엔드 + Vercel" 조합을 생각했으나, Vercel이 Java를 지원하지 않고 이 앱은 로그인이 없어 별도 서버가 필요하지 않다는 설명을 듣고 백엔드 없이 프론트에서 Supabase에 직접 연결하는 방식으로 변경.

## 보안 점검 메모
- 프론트 코드(`js/supabaseClient.js`)에는 anon(public) key만 넣는다. service_role key는 어디에도 넣지 않는다.
- 모든 사용자 입력은 `js/utils.js`의 `escapeHtml()`을 거쳐 렌더링되며, `innerHTML`에 원문을 직접 삽입하지 않는다.
- 배포 전 브라우저 개발자도구 Network/Console, 배포 파일, Git 커밋 이력에 비밀키가 없는지 확인한다.

# T07 — 인증(가입/로그인/로그아웃) 붙이기

T06에 이어서 가입/로그인/로그아웃을 붙였다. **더 이상 로그인 없이 접근 가능한 공개 앱이 아니다** —
첫 화면은 로그인 화면이고, 로그인해야만 내 계획·할 일·실행 기록이 보인다.
자세한 설계 이유·수정 위치·증거는 `T07_AUTH_EXPLANATION.md`, 항목별 체크는 `T07_REQUIREMENTS_CHECKLIST.md` 참고.

## T07 추가 설정
1. `sql/schema-v3-auth.sql`을 Supabase SQL Editor에서 실행 (users/sessions 테이블, RLS 잠금).
2. T06 시절 데이터가 있다면 `sql/migrate-t06-data-to-owner.sql`로 실제 계정에 이관.
3. Vercel 프로젝트 Settings → Environment Variables에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`(Supabase의 secret/service_role 키), `JWT_SECRET`(임의의 긴 랜덤 문자열)을 등록 후 재배포.

## 짧은 확인 방법 (T07, 4줄)
- **어디로 가나요**: https://ex-6-seven.vercel.app/
- **세 단계 안에 무엇을 하나요**: ① 계정 A로 가입·로그인해 계획을 하나 만든다 ② 로그아웃 후 계정 B로 새로 가입·로그인한다 ③ 계정 B 화면에서 계정 A의 계획이 목록에 보이거나 그 계획의 주소로 직접 접근해본다
- **무엇이 보이면 통과인가요**: 계정 B의 "현재 계획" 목록에 계정 A의 계획이 전혀 없고, 계정 A의 계획 id로 직접 요청해도(`/api/data/plans?id=...`) `not found`만 돌아온다
- **안 될 때는 무엇이 보이나요**: 계정 B 화면에 계정 A의 계획이 나타나거나, 그 계획을 수정·삭제할 수 있다
